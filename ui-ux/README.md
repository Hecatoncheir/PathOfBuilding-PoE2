# Мастерская Path of Building

Ветка `ui/ux`. Первая стадия — самостоятельный HTML/JS-прототип интерфейса. Откройте `index.html` в браузере или запустите `python -m http.server 8765` из корня репозитория и перейдите на `http://localhost:8765/ui-ux/`.

## Направление дизайна

Палитры [Gruvbox](https://github.com/morhetz/gruvbox): тёмный тёплый фон и светлый кремовый фон, оливковый для действий, жёлтый для игровых объектов, красный для предупреждений. Светлая тема доступна кнопкой в шапке. Светлый жёлтый акцент затемнён для читаемости текста на кремовых поверхностях; заливка выбранных узлов, свечение дерева и фон диалога также зависят от темы. Плотность подходит для длительной работы: мало декоративных элементов, узнаваемые разделы, показатели в постоянном контексте. На телефоне разделы становятся горизонтальной навигацией, показатели идут после редактора. Сенсорные кнопки имеют высоту не менее 44 px. Анимации короткие, учитывают `prefers-reduced-motion`.

Возвращаться удобно благодаря сохранению последнего раздела, локальным заметкам и продолжению текущей сборки. Без искусственных серий посещений и уведомлений. Шрифт Manrope загружается из Google Fonts; при отсутствии сети используется системный шрифт. Других внешних ресурсов и зависимостей нет.

## Что действительно работает

Навигация по девяти разделам; переключение темы; выбор уровня, набора и цели; схематичное дерево с выбором узлов, поиском, масштабированием и перемещением мышью или касанием; перенос предметов в совместимые слоты и альтернативная кнопка «Надеть»; включение умений и условий; заметки; отмена изменений; локальное сохранение; проверяемый импорт и экспорт JSON состояния прототипа; быстрый переход Ctrl/Cmd+K.

Это демонстрационный интерфейс, а не новый игровой калькулятор. Дерево схематичное, предметы и числа примерные. Прототип не читает XML сборок, коды PoB, данные персонажей или Lua. Числа не изменяются при выборе узлов: выдумывать игровые результаты было бы неправильно. Часть элементов показывает будущую структуру редакторов и явно описывает ограничение.

| ItemsTab / ItemDBControl / TradeQuery* | Снаряжение + библиотека + мастерская | Все слоты и наборы, вставка текста предмета, уникальные и редкие предметы, крафт, роллы, качество, осквернение, произвольные модификаторы, торговля, сравнение |
| SkillsTab / SkillsSetService | Умения + группы камней | Все активные и поддерживающие умения, качество, уровень, наборы, источники предметов, автоматические поддержки, drag&drop |
| ConfigTab / ConfigSetService | Условия боя + расширенные параметры | Все исходные настройки, наборы, ауры, проклятия, заряды, состояния, резервации, пользовательские модификаторы |

| CompareTab / CompareBuySimilar | Сравнение | Сборки, предметы, одинаковые сценарии, отчёты по улучшениям, торговые запросы |
| PartyTab / Minion* | Группа и приспешники | Состав группы, эффекты союзников, списки и поиск приспешников/спектров, их параметры |
| NotesTab | Заметки | Полный текст, ссылки, совместимость с сохранением сборки |

Карта — обязательства для переноса, а не утверждение о готовности функций. Перед заменой интерфейса нужен полный реестр контролов исходных модулей и проверка каждой функции на существующих сборках.

## Следующая стадия: Flutter

Flutter в этом репозитории пока не добавлен. Нельзя безопасно заменить текущий Lua-интерфейс одним визуальным экраном.

1. Зафиксировать эталонные сборки и результаты текущего движка: дерево, предметы, умения, приспешники, группа, условия, сравнение и round-trip XML.
2. Выделить контракт `BuildEngine`: загрузка/сохранение, команды изменений, undo/redo, расчёты, описание источников, каталоги и события. UI получает настоящий результат движка, а не вычисляет формулы в Dart.
3. Проверить возможность изоляции Lua от существующего графического runtime. Для desktop рассмотреть отдельный процесс с версионированным протоколом; для mobile — встроенный runtime через FFI. Решение принимается после технического эксперимента, а не заранее. Без этой работы мобильная функциональная совместимость не гарантируется.
4. Перенести оболочку на `NavigationRail` / компактную навигацию, цветовые токены на `ThemeExtension`, дерево на `CustomPainter` + `InteractiveViewer`, предметы на `Draggable` / `DragTarget`. На сенсорном экране дополнительно нужны длительное нажатие, просмотр узла перед назначением, pinch zoom и явные действия вместо обязательного hover.
5. Добавить библиотеку с несколькими сборками, миграции состояния, автосохранение, подтверждение потери несохранённых изменений, обработку ошибок импорта, локализацию и доступность дерева для клавиатуры/экранного диктора.
6. Подключать разделы последовательно. Замена текущего интерфейса допустима после проверки полного реестра, совпадения расчётов и форматов сохранения. Обновления и торговля требуют отдельных платформенных адаптеров.

## Проверка

Синтаксис: `node --check ui-ux/app.js`. Ручные сценарии: выбрать/отменить узел, найти узел, переместить и масштабировать дерево; перетащить кольцо в правильный и неправильный слот; надеть предмет без переноса; изменить условия; сохранить заметки и перезагрузить страницу; экспортировать/импортировать JSON; отклонить неверный JSON; проверить темы и ширины 360, 768, 1440 px. Импортировать нужно только JSON прототипа, не игровые сборки.
