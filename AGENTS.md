# Repository Guidelines

## Структура проекта

`src/` содержит приложение на Lua: `Modules/` — запуск и логика сборок, `Classes/` — интерфейс и сервисы, `Data/` — игровые данные, `TreeData/` — деревья и ресурсы, `Export/` — генераторы данных. `runtime/` содержит Windows runtime и библиотеки Lua. Системные тесты находятся в `spec/System/`, Python-тесты — в `tests/`.

`ui-ux/` — самостоятельный HTML/JS-прототип с темами Gruvbox. `docs/flutter/` содержит реестр функций и эталоны; `tools/` — вспомогательные сценарии. План переноса находится в `TODO.md`; Первая Windows-основа находится в `app/`; команды: `flutter analyze`, `flutter test`, `flutter run -d windows` из её каталога.

## Разработка и проверка

Выполняйте команды из корня репозитория, если не указано иное:

- Windows: `& './runtime/Path{space}of{space}Building-PoE2.exe'` запускает существующее приложение.
- `python -m http.server 8765` открывает прототип по адресу `/ui-ux/`.
- `node --check ui-ux/app.js` проверяет синтаксис JavaScript.
- `python tools/flutter_inventory.py` обновляет статический реестр исходных модулей.
- `python tools/run_headless.py tools/headless_smoke.lua` проверяет расчёт через Windows runtime; перезаписывает эталонные файлы Fireball.
- `python tools/run_headless.py tools/check_headless_baseline.lua` сравнивает результаты с сохранённым эталоном без его перезаписи.
- `python tools/check_engine_protocol.py` проверяет команды экспериментального процесса движка и ошибки протокола.
- `busted --lua=luajit ../spec/System/TestOffence_spec.lua` запускает один системный тест с конфигурацией `.busted`; требует Busted/LuaJIT, как в CI.
- `git diff --check` проверяет ошибки пробелов перед коммитом.

## Стиль и именование

Для Lua используйте табуляцию и настройки `.editorconfig`; имена файлов и классов согласуйте с соседними модулями, например `ItemsTab.lua`. Python оформляйте с четырьмя пробелами и именами `snake_case`. Снижайте когнитивную сложность: небольшие функции, явные зависимости, минимум вложенности.

Общение, пояснения и новые комментарии пишите на русском языке. Сохраняйте оригинальные имена API и технические термины. Не редактируйте автоматически генерируемые игровые данные вручную: меняйте генератор и проверяйте результат.

## Тестирование

Lua-тесты используют Busted и именуются `Test…_spec.lua`. Добавляйте проверки поведения и регрессий в соответствующий раздел. Обязательный процент покрытия не установлен; конфигурация Busted отключает сбор покрытия. Проверяйте расчёты, импорт/экспорт и повторное сохранение. Изменения интерфейса проверяйте в обеих темах на узком и широком экране. Smoke-проверка не заменяет полный набор тестов.

## Коммиты и pull request

История использует короткие описания действий: `Fix…`, `Add…`, `Update…`; последние изменения этой ветки описаны по-русски. Делайте тематические коммиты. В pull request объясняйте проблему, результат и выполненные проверки; соблюдайте `.github/pull_request_template.md`, прикладывайте связанные issues и снимки интерфейса. Для upstream целевая ветка — `dev`, согласно `CONTRIBUTING.md`.

## Перенос на Flutter

Сохраняйте Lua источником игровых расчётов. Не выдавайте демонстрационные показатели за реальные. Отмечайте функциональное соответствие только после проверки; не включайте токены аккаунтов и личные данные в эталоны.
