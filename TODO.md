# План создания приложения на Flutter

Цель: перенести Path of Building для PoE2 на Flutter с дизайном мастерской из [HTML-прототипа](ui-ux/index.html), темами Gruvbox и сохранением всей функциональности текущего форка.

Начальное состояние: готов визуальный HTML/JS-прототип; Создана первая Windows-основа Flutter с процессным Lua-клиентом; полный перенос ещё не выполнен. Незавершённые задачи ниже остаются открытыми. Примерные числа, предметы и схематичное дерево прототипа не являются игровыми данными.

Подготовка этапа 1 начата: созданы [первичный реестр функций](docs/flutter/feature-parity.md), [статический реестр 42 модулей](docs/flutter/source-inventory.md) и [план эталонных данных](docs/flutter/baseline-plan.md). Реестр обновляется командой `python tools/flutter_inventory.py`. Ручной обход приложения, запуск Lua-тестов и получение эталонных XML ещё не выполнены, поэтому этап не отмечен завершённым.

## Правила реализации

- Текущий Lua-калькулятор — источник игровых формул и результатов. Не переписывать формулы в Dart ради быстрого макета.
- Существующее приложение остаётся доступным до достижения функционального соответствия.
- Сначала Windows как проверочная платформа текущего проекта, затем Android/iOS и macOS/Linux. Поддержку браузера исследовать отдельно: процессный адаптер и FFI туда напрямую не переносятся.
- Разделять состояние сборки, состояние интерфейса и вычисленные результаты. Использовать небольшие компоненты и явные команды; сохранять низкую когнитивную сложность.
- Каждой существующей функции сопоставить экран, команду движка и проверку. Раздел не считается готовым по одному только внешнему виду.
- Не устанавливать сторонние пакеты и MCP без согласия пользователя. До добавления зависимости записать назначение, точную команду, первичный источник и лицензию.

## Порядок первых итераций

1. Реестр функций и эталонные сборки — этап 1.
2. Работающий Lua без старого интерфейса — этап 2; это главное техническое условие продолжения.
3. Контракт и минимальная Flutter-оболочка — этапы 3–5.
4. Первая сквозная версия: открыть XML → изменить реальный узел → увидеть новый расчёт → отменить → сохранить — минимальные части этапов 6, 7 и 10.

6. Проверка платформ, качества и выпуск — этапы 12–13. Проверки отдельных функций выполняются на протяжении всех итераций.
